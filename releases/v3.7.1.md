# v3.7.1

Patch release fixing managed Antigravity executable discovery, `--` forwarding
after a bare command, and UTF-8 C1 filtering in the PTY primary-screen filter.

Backward compatible: no config schema, default capability, or flag behavior is
weakened.

## Fixed

- **PTY `TerminalFilter` UTF-8 C1 lead-byte handling (GHSA-x757-f885-jf96, PR
  #266).** Hold `0xc2` lead bytes consistently when returning to `Ground` from
  a truncated `0xc2` lead or a lone `ESC`, so encoded C1 control pairs are
  dropped while legitimate non-C1 continuations pass through unchanged. Thanks
  @eolobinhooooooooooooooohhoooooo for reporting privately.

- **Forward `--` after a bare command to the child (#264, PR #265).** A `--`
  before the command continues to terminate `ai-jail`'s own options, while a
  `--` after a bare command (for example `ai-jail grep -- -v pattern` or
  `ai-jail git checkout -- src/main.rs`) is now forwarded verbatim to the child
  instead of being stripped. Thanks @eolobinhooooooooooooooohhoooooo.

- **Resolve managed Antigravity executable as `agy` (PR #263).** Map canonical
  `antigravity` to `agy` in `ManagedHarness::executable()` when `--executable`
  is not passed, so `ai-memory run --jail agy` locates the host binary and
  exempts its directory under private home. Thanks @leonardovrezende.
