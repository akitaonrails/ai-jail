# v1.17.0

## Docker socket discovery now honors `$DOCKER_HOST` (PR #94)

The `--docker` option used to hardcode `/var/run/docker.sock`. That broke on
rootless Docker and rootless Podman setups, where the compat symlink at
`/var/run/docker.sock` may point to a root-only socket that the user cannot
reach, causing bwrap to abort the whole launch.

### Changed

- `ai-jail --docker` now resolves the socket using the same priority as the
  Docker CLI:
  1. `$DOCKER_HOST` when it is an absolute `unix://` path and the socket is
     reachable.
  2. `/var/run/docker.sock` if reachable.
  3. `~/.docker/run/docker.sock` if reachable.
- Non-`unix://` `$DOCKER_HOST` values (`tcp://`, `ssh://`, `npipe://`) are not
  bindable paths and are ignored, so existing network-based configurations keep
  their previous behavior.
- Unreachable symlinks are skipped instead of mounted, fixing the launch abort
  on rootless Podman.

### Compatibility

- Existing setups that rely on `/var/run/docker.sock` continue to work
  unchanged.
- Only when `$DOCKER_HOST` points to a reachable unix socket does it take
  precedence over the well-known paths.

### Validation

- Added unit tests for `$DOCKER_HOST` precedence, unreachable fallback,
  non-unix endpoint filtering, and the unfollowable-symlink regression.
- Updated `README.md` with the new resolution order and a note about exporting
  `$DOCKER_HOST` for rootless engines.
