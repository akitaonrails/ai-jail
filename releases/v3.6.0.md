# v3.6.0

Named configuration profiles, per-run observability (`--run-summary`,
`--teardown-report`, exit-reason diagnostics), configurable Linux per-process
resource limits (`--rlimit`) and CPU affinity (`--cpus`), plus a Linux Landlock
fix for eCryptfs-backed directories.

Backward compatible: all new controls are opt-in, existing launches and saved
policies keep their prior behavior, and monotonic project-policy rules are
preserved.

## Added

- **Named configuration profiles (`[profiles.NAME]` / `--profile NAME`, #230,
  PR #250).** Define reusable profile tables in the trusted global config and
  select one per launch with `--profile`. Effective widenings relative to the
  baseline (including credential bindings, mounts, limits, and CPUs) are
  reported visibly and recorded in the launch audit entry. Thanks @lucascouts.

- **Per-run observability: exit-reason diagnostics (#242, PR #247), in-sandbox
  teardown reporting (`--teardown-report`, #249, PR #251), and private run
  summaries (`--run-summary <PATH>`, #228, PR #252).**
  - Runs that end due to a signal or resource limit print a concise stderr
    diagnostic distinguishing observed causes from inferred signals.
  - `--teardown-report` (Linux) reaps background processes that outlive the
    jailed command inside the private PID namespace, verifies signal targets,
    and reports survivors through an isolated close-on-exec pipe.
  - `--run-summary <PATH>` writes a single versioned, mode-`0600` JSON report
    combining exit status, teardown survivors, child resource usage, run ID,
    and filtered-egress counts without affecting the command's exit code.
    Thanks @lucascouts.

- **Configurable Linux per-process resource limits (`--rlimit NAME=VALUE`,
  #229, PR #253).** Adjust per-process limits (`nofile`, `nproc`, `core`,
  `cpu`, `as`, `fsize`, etc.) on the CLI or in config. Limits are validated
  before status, onboarding saves, and launch; project constraints can only
  tighten limits; host supervisor limits stay independent from child command
  limits; and explicit limits are shown in effective-access review, dry run,
  and the launch audit log. Thanks @lucascouts.

- **Linux CPU affinity (`--cpus LIST`, #229, PR #254).** Pin jailed commands
  to an explicit CPU set without root or systemd, enforced inside the sandbox
  with seccomp blocking affinity changes. Project policies may only narrow the
  CPU set, and CPUs added by a named profile are reported in the widening
  summary. Thanks @lucascouts.

- **Linux ARM64 release archives and tested global config example.** Release
  CI now builds and attests `aarch64-unknown-linux-gnu` archives alongside
  x86-64 and macOS, and `docs/config.example.toml` provides a tested reference
  global configuration.

## Fixed

- **Landlock `readdir` on eCryptfs-backed directories (#243, PR #255).**
  eCryptfs opens the underlying lower directory under the caller's credentials
  during `readdir` (`ecryptfs_dir_open`), which Landlock denied with `EACCES`
  because the lower tree is not mounted inside the sandbox. On Linux, `ai-jail`
  now detects `ecryptfs` mounts in `/proc/self/mountinfo` (including
  filename-encrypted `ecryptfs_fnek_sig` mounts), opens the matching lower
  directory with `O_PATH | O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`, grants
  `AccessFs::ReadDir` only in the Landlock ruleset, and closes all lower
  descriptors before seccomp and `exec` while keeping the lower directory
  unmounted from the sandbox. Thanks @Covre81 for tracing the root cause.

- **macOS Codex startup services stay independent of agent state.** Keep
  required Codex startup services reachable without coupling them to optional
  agent-state mounts.
