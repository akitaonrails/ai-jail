# v1.16.0

## Docker socket passthrough is now opt-in

This release closes the sandbox escape reported in #88. Previously, ai-jail
bind-mounted the raw host Docker socket read-write into the sandbox whenever
`/var/run/docker.sock` existed — with no opt-in and no warning. Because the
Docker daemon runs as root on the host, a sandboxed agent could escape every
bubblewrap/Landlock/seccomp restriction by starting a container with an
arbitrary host bind mount (`docker run -v /:/host ...`), defeating tmpfs
`$HOME`, `--mask`, `--deny-path`, and Landlock.

### Changed

- Docker socket passthrough no longer auto-enables when the socket exists.
  It is exposed only when explicitly requested via `--docker` or
  `no_docker = false` in the config.
- When passthrough is enabled and a host Docker socket is present, ai-jail
  prints a launch warning that the sandboxed process gets effective root on
  the host through the Docker daemon, bypassing `--mask`, `--deny-path`,
  and Landlock.
- Status output now reports Docker as `disabled (default)` unless
  explicitly enabled; the README security notes spell out the consequence
  of enabling it.
- When a project `.ai-jail` enables dangerous opt-ins (Docker, Tailscale,
  SSH, Pictures, systemd user bus, or host path maps outside the project)
  that are not already enabled in the user's global config or on the CLI,
  ai-jail prints a launch warning so a cloned/malicious repo cannot
  silently weaken the sandbox.
- The internal `--landlock-rw-path` and `--landlock-ro-path` wrapper flags
  are now rejected at the outer CLI unless `--landlock-exec` is also set.

### Compatibility

- **Behavior change:** existing setups that relied on the implicit
  auto-enable must opt in once — pass `--docker` or set
  `no_docker = false` in `.ai-jail`. Old config files keep parsing
  unchanged; only the unset default changed.
- `--no-docker` / `no_docker = true` behave exactly as before. Lockdown and
  browser profile modes never expose the socket, as before.

### Validation

- Updated the `docker_enabled` accessor test: unset now means disabled.
- Added tests for the warning gate: passthrough requires explicit opt-in
  and stays off in lockdown and browser profile modes even when enabled.
